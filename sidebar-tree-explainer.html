Hextra Sidebar Tree: How This Branch Builds and Renders Navigation

A simplified walkthrough of the sidebar rewrite in this branch. The important idea is that Hugo templates first build a typed node tree, then render a small stable contract that browser JavaScript enhances for active state, section expansion, and mobile table of contents.

data-first sidebar auto fallback type: separator JS active state mobile TOC injection
Current branch state: includes open inheritance and fallback cleanup.
Main files: layouts/_partials/sidebar.html, components/sidebar/*, assets/js/core/sidebar.js
Tests: tests/sidebar.spec.ts

Pipeline

The sidebar is built in five phases. The desktop and mobile sidebars share the same render tree, but they use different roots and scopes.

1 Detect source

source-data.html looks for the best matching data file for the current section.

2 Build tree

build-tree.html chooses data nodes when matched, otherwise auto nodes.

3 Normalize

normalize-node.html resolves links, titles, icons, open state, and node type.

4 Render

render-tree.html and render-item.html consume the normalized tree.

5 Enhance

Inline JS and sidebar.js mark active links, open ancestors, restore state, and inject TOC.

Source Detection

For a page under /docs/guide/configuration/, the branch looks up a localized data file first. If a matching data file exists, that data file is authoritative for the covered section. Sections not covered by data fall back to the content tree. 

// sidebar.html
matchFound = len(sourceData(currentPage, lang, sectionKey)) > 0

desktopNodes = buildTree({
  context: navRoot,
  page: currentPage,
  matched: matchFound,
  scope: "desktop"
})

mobileNodes = buildMobileTree({
  page: currentPage,
  matched: matchFound
})

Data Model

Data nodes now use type for virtual nodes. A separator is just type: separator; the older data-file shape separator: true is no longer accepted. 

- type: search

- link: /docs/guide/
  merge: deep

- type: separator
  title: Deep Dive

- link: /docs/sidebar-lab/
  title: Sidebar Lab
  icon: folder-tree
  merge: deep
  items:
    - link: /docs/sidebar-lab/manual-only/
    - link: /docs/sidebar-lab/manual-parent/
      merge: none

What Normalization Adds

The raw data file is intentionally compact. Normalization resolves missing values from Hugo pages.

Input Resolved by Result
link: /docs/guide/ utils/sidebar-link.html Language-aware URL such as /docs/guide/.
Missing title Linked page title Guide
Missing icon Linked page Params.sidebar.icon book-open, folder-tree, etc.
Missing open Linked page Params.sidebar.open sidebar.open: true on docs/guide/_index.md keeps Guide expanded.
type: separator Node type validation Rendered as a label; its children, if any, are lifted beside it.

Merge Modes

Data order is authoritative. merge decides whether the node shows only explicit children or also appends unmatched auto-discovered children.

// merge: none
Manual Parent
  Manual Node
  // Auto children under this page are not appended.

// merge: deep
Deep Parent
  Deep Manual Node
  Deep Auto Child
  // Missing pages from content tree are appended.
Data node weight was removed. Explicit data order is the ordering mechanism. Page weight still matters for auto-discovered children via sorted-items.html.

Exclude Handling

Exclusion now goes through one predicate, is-excluded.html. The tree builders pass a scope, so future values such as exclude: mobile or a scope list have one place to evolve. 

isExcluded({ page, scope: "desktop" })
isExcluded({ page, scope: "mobile" })
isExcluded({ node, scope })

// Current semantics:
exclude: true       // hidden everywhere
exclude: mobile     // supported by the predicate
exclude: [mobile]   // supported by the predicate

Render Contract

Render templates only depend on a small set of fields. Builders may carry extra helper fields while assembling the tree, but rendering reads the stable fields below.

{
  type: "separator" | "search" | "",
  link: "/docs/guide/",
  title: "Guide",
  items: [...],
  open: true,
  icon: "book-open"
}

Active State and Expansion

Server rendering starts with default open state. JavaScript then finds the current URL, marks the active link, and opens every ancestor li.

if (normalize(link.href) == normalize(location.pathname)) {
  link.classList.add("hextra-sidebar-link-active")
  link.setAttribute("aria-current", "page")

  li = link.closest("li")
  while (li) {
    li.classList.add("open")
    setButtonExpanded(li, true)
    li = parentSidebarLi(li)
  }
}

No JS

The noscript fallback now forces children visible with layout-agnostic CSS instead of depending only on grid-template-rows.

.hextra-sidebar-children {
  display: block !important;
  height: auto !important;
  max-height: none !important;
  overflow: visible !important;
  grid-template-rows: none !important;
}

Mobile TOC

Mobile TOC is stored in a <template>. JavaScript injects it under the active mobile item. If mobile active is absent, it uses the desktop active href to find the mobile match, then falls back to an open or first mobile item. 

active = mobile.querySelector(".active")
if (!active) {
  href = desktopActive.href
  active = findMobileLinkByHref(href)
}
target = activeLi || openLi || firstLi

Icon Markup

Repeated icon wrapper markup is centralized in sidebar-icon.html. Link rows, group titles, and separators all use the same partial.

{{ partial "components/sidebar/sidebar-icon.html" $node.icon }}
